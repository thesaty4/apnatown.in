## Application structure and dependency rules

```text
apps/api/src/
  modules/<module>/
    presentation/     # controllers, request/response DTO adapters
    application/      # use-cases, policies, transaction orchestration
    domain/           # entities, value objects, events, repository ports
    infrastructure/   # SQL/ORM repositories, external adapters
  shared/
    config/ logger/ errors/ validation/ auth/ persistence/ events/
    jobs/ idempotency/ rate-limit/ i18n/ openapi/
  integrations/
    payments/ otp/ whatsapp/ email/ storage/ maps/
```

| Layer | May depend on | Must not |
|---|---|---|
| Presentation | Shared validation/auth, its module's application use-cases | Call repositories, contain business rules, expose ORM entities |
| Application | Its module's domain, shared ports, explicitly allowed module application interfaces | Import a concrete DB client or provider SDK |
| Domain | Pure types, policies and repository/event interfaces | Import NestJS, ORM, HTTP, or integration packages |
| Infrastructure | Its module's domain ports, shared persistence, provider adapters | Be imported by another module's domain/application layer |

Use the module dependency list in [architecture.md](./architecture.md). Shared schemas/types/status maps live in `packages/shared`; public APIs are REST and generated from DTOs. Use-cases own transaction boundaries and invoke a repository only through its interface. Integration adapters have fakes; provider credentials never leave adapters. See [backend instructions](../../.github/instructions/backend.instructions.md), [database instructions](../../.github/instructions/database.instructions.md), and [integration instructions](../../.github/instructions/integrations.instructions.md).

## Shared layer

| Item | Purpose and usage rule |
|---|---|
| Config | Typed env parsing at startup; reject missing/invalid required configuration and never log secrets. |
| Logger + correlation ID | Structured Pino logs; create/propagate `correlationId` across HTTP, outbox and jobs; redact secrets and PII. |
| Exception filter | Map typed domain/validation failures to the stable error contract below; never return stack traces. |
| Validation pipe | Zod DTO allow-lists; reject unknown keys, transform only declared fields, and reuse the same schemas for OpenAPI. |
| CSV/slug/UUID pipes | CSV size/row/type validation and formula-safe export; normalize/validate slugs; reject malformed UUIDs before use-cases. |
| `Money` | Integer paise value object; server-only arithmetic and named rounding rules; no floating-point amounts. |
| Clock + ID providers | Inject `Clock` and UUIDv7 `IdProvider`; tests use deterministic fakes, production IDs are generated by the application. |
| Pagination | Opaque keyset cursor with stable tie-breaker; default limit and hard cap 50; no offset for feeds/queues. |
| Base repository + unit of work | Shared transaction and pagination primitives only; domain-specific queries stay in the owning repository. |
| `@Roles`, `@Permission(module, action)`, `@Scoped` | Metadata only; attach to protected handlers and enforce through guards on every request. |
| Guards + ownership policy | Verify authenticated role, module/action permission, admin city/area scope and resource ownership; `super_admin` scope is platform-wide only where specified. |
| Idempotency interceptor | Require key for specified mutations; store actor + operation + request hash + result; same key/same payload replays, same key/different payload conflicts. |
| Audit interceptor | Emit before/after audit records for sensitive mutations; fail the mutation if required audit persistence fails. |
| Rate-limit guard | Shared policy per route/actor/phone; use atomic PostgreSQL counters at launch (no Redis); apply tighter OTP/send limits from auth module specs. |
| Outbox publisher + job runner | Write `outbox_events` in the same DB transaction as state changes; publish to pg-boss with stable event IDs; retry idempotently and alert terminal failures. |
| Adapter interfaces + fakes | Ports for payment, OTP/SMS, WhatsApp, email, storage and maps; unit tests inject deterministic fakes. |
| Settings/feature flags | Typed server-side reads; no client-supplied flag may authorize an action. |
| OpenAPI | Generate from DTO/Zod schemas; version REST routes deliberately and publish stable error shapes. |
| i18n message catalogue | `en` and `hi` message keys for user-visible API errors/templates; API returns key and safe parameters, clients render localized copy. |

### Error contract

```json
{
  "code": "ORDERS_INVALID_TRANSITION",
  "message_key": "errors.orders.invalidTransition",
  "status": 409,
  "details": { "field": "status" },
  "correlationId": "uuid"
}
```

`code` is stable and uppercase: `<MODULE>_<REASON>`; `message_key` is localized by the client. `details` contains only allow-listed, non-sensitive fields. Validation errors may include field paths, never submitted values. HTTP status and `status` match. Common codes: `COMMON_VALIDATION_FAILED` (400), `COMMON_UNAUTHENTICATED` (401), `COMMON_FORBIDDEN` (403), `COMMON_NOT_FOUND` (404), `COMMON_CONFLICT` (409), `COMMON_RATE_LIMITED` (429).

This follows the LEAN SPECS contract; reconcile it with the earlier candidate envelope under [Q-26](../../docs/design-context/11-open-issues-and-assumptions.md) before generating clients.

## Catalog reference slice

Reference only; module specs own final DTO, tables and endpoint definitions.

```ts
// domain/subcategory-suggestion.ts
export type SuggestionStatus = 'pending' | 'approved' | 'rejected' | 'merged';

export interface SubcategorySuggestion {
  id: string;
  categoryId: string;
  nameEn: string;
  nameHi: string;
  normalizedName: string;
  submittedBy: string;
  status: SuggestionStatus;
}

export interface SubcategorySuggestionCreated {
  eventId: string;
  suggestionId: string;
  categoryId: string;
}
```

```ts
// presentation/suggestion.dto.ts
import { z } from 'zod';

export const suggestSubcategorySchema = z.object({
  categoryId: z.string().uuid(),
  nameEn: z.string().trim().min(2).max(60),
  nameHi: z.string().trim().min(2).max(80),
}).strict();

export const resolveSuggestionSchema = z.discriminatedUnion('decision', [
  z.object({ decision: z.literal('approve') }).strict(),
  z.object({ decision: z.literal('reject'), reason: z.string().trim().min(1).max(500) }).strict(),
  z.object({ decision: z.literal('merge'), targetId: z.string().uuid() }).strict(),
]);
```

```ts
// domain/subcategory-suggestion.repository.ts
import { z } from 'zod';

export interface SubcategorySuggestionRepository {
  findSimilar(categoryId: string, normalizedName: string): Promise<boolean>;
  createPending(input: Omit<SubcategorySuggestion, 'status'>, event: SubcategorySuggestionCreated): Promise<SubcategorySuggestion>;
  resolve(id: string, decision: z.infer<typeof resolveSuggestionSchema>, actorId: string): Promise<SubcategorySuggestion>;
}
```

```ts
// infrastructure/prisma-subcategory-suggestion.repository.ts
import { PrismaClient } from '@prisma/client';
import { z } from 'zod';

export class PrismaSubcategorySuggestionRepository implements SubcategorySuggestionRepository {
  constructor(private readonly db: PrismaClient, private readonly ids: IdProvider) {}

  async findSimilar(categoryId: string, normalizedName: string): Promise<boolean> {
    const [existing, pending] = await Promise.all([
      this.db.subcategory.findFirst({ where: { categoryId, normalizedName }, select: { id: true } }),
      this.db.subcategorySuggestion.findFirst({ where: { categoryId, normalizedName, status: 'pending' }, select: { id: true } }),
    ]);
    return existing !== null || pending !== null;
  }

  createPending(input: Omit<SubcategorySuggestion, 'id' | 'status'>, event: SubcategorySuggestionCreated) {
    return this.db.$transaction(async (tx) => {
      const suggestion = await tx.subcategorySuggestion.create({ data: { ...input, status: 'pending' } });
      await tx.outboxEvent.create({ data: { id: event.eventId, type: 'catalog.subcategory-suggested', payload: { suggestionId: suggestion.id, categoryId: suggestion.categoryId } } });
      return suggestion;
    });
  }

  resolve(id: string, decision: z.infer<typeof resolveSuggestionSchema>, actorId: string) {
    return this.db.$transaction(async (tx) => {
      const current = await tx.subcategorySuggestion.findUnique({ where: { id } });
      if (!current || current.status !== 'pending') throw new ConflictError('CATALOG_SUGGESTION_NOT_PENDING');
      let targetId: string | null = null;
      if (decision.decision === 'merge') {
        const target = await tx.subcategory.findFirst({ where: { id: decision.targetId, categoryId: current.categoryId } });
        if (!target) throw new NotFoundError('CATALOG_MERGE_TARGET_NOT_FOUND');
        targetId = target.id;
      }
      const status = decision.decision === 'approve' ? 'approved' : decision.decision === 'reject' ? 'rejected' : 'merged';
      const changed = await tx.subcategorySuggestion.updateMany({
        where: { id, status: 'pending' },
        data: { status, resolvedBy: actorId, targetId, rejectionReason: decision.decision === 'reject' ? decision.reason : null },
      });
      if (changed.count !== 1) throw new ConflictError('CATALOG_SUGGESTION_NOT_PENDING');
      if (decision.decision === 'approve') {
        await tx.subcategory.create({ data: { categoryId: current.categoryId, nameEn: current.nameEn, nameHi: current.nameHi, normalizedName: current.normalizedName } });
      }
      await tx.outboxEvent.create({ data: { id: this.ids.uuidv7(), type: 'catalog.subcategory-suggestion-resolved', payload: { suggestionId: id, status } } });
      return tx.subcategorySuggestion.findUniqueOrThrow({ where: { id } });
    });
  }
}
```

```ts
// application/subcategory-suggestion.use-case.ts
import { z } from 'zod';

export class SuggestSubcategory {
  constructor(
    private readonly repo: SubcategorySuggestionRepository,
    private readonly ids: IdProvider,
  ) {}

  async execute(input: z.infer<typeof suggestSubcategorySchema>, actorId: string) {
    const normalizedName = input.nameEn.normalize('NFKC').trim().toLocaleLowerCase('en');
    if (await this.repo.findSimilar(input.categoryId, normalizedName)) {
      throw new ConflictError('CATALOG_SUBCATEGORY_DUPLICATE');
    }
    const suggestionId = this.ids.uuidv7();
    return this.repo.createPending(
      { id: suggestionId, ...input, normalizedName, submittedBy: actorId },
      { eventId: this.ids.uuidv7(), suggestionId, categoryId: input.categoryId },
    );
  }
}

export class ResolveSuggestion {
  constructor(private readonly repo: SubcategorySuggestionRepository) {}

  execute(id: string, decision: z.infer<typeof resolveSuggestionSchema>, actor: AuthenticatedUser) {
    return this.repo.resolve(id, decision, actor.id);
  }
}
```

```ts
// presentation/catalog.controller.ts
@Controller('catalog/subcategory-suggestions')
export class CatalogController {
  constructor(private readonly suggest: SuggestSubcategory, private readonly resolve: ResolveSuggestion) {}

  @Post()
  @UseGuards(SessionGuard, RolesGuard)
  @Roles('vendor', 'provider')
  submit(@Body(new ZodPipe(suggestSubcategorySchema)) dto: z.infer<typeof suggestSubcategorySchema>, @CurrentUser() user: AuthenticatedUser) {
    return this.suggest.execute(dto, user.id);
  }

  @Post(':id/resolve')
  @UseGuards(SessionGuard, RolesGuard, PermissionGuard, AdminScopeGuard)
  @Roles('admin', 'super_admin')
  @Permission('catalog', 'edit')
  @Scoped()
  resolveSuggestion(@Param('id', ParseUUIDPipe) id: string, @Body(new ZodPipe(resolveSuggestionSchema)) dto: z.infer<typeof resolveSuggestionSchema>, @CurrentUser() user: AuthenticatedUser) {
    return this.resolve.execute(id, dto, user);
  }
}

```

`ResolveSuggestion` must atomically allow only `pending -> approved/rejected/merged`, validate the merge target and record an audit event. Controller guards check role/permission/scope; use-case checks state and duplicate rules; repository implementation is parameterized and uses the owning module's transaction.
